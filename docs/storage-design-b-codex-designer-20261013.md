**3. 推薦（b），並固定以下實作契約**

理由：這個產品需要孩子可靠地完成複習，沒有必須同時在兩個分頁答題的需求。限制寫入者，可以直接移除整個多快照合併問題，也能保留 R2 要求的「暫時存不了，已答內容仍留在記憶體」。

這與[難題站設計 C:9](/Users/william/Documents/g5-help/docs/storage-design-C-4agent-20261013.md:9)的方向一致；該文件後續還縮限了同步衝突選擇，不能只引用前半段。[設計 C:28](/Users/william/Documents/g5-help/docs/storage-design-C-4agent-20261013.md:28)

建議將契約固定為：

1. **取鎖且讀取成功，才接受修改。**  
   使用專屬鎖名，例如 `g5wrong.v1:writer`，持有期間涵蓋整個可寫頁面的生命週期。其他頁面唯讀，作答、清除、隱藏、恢復、提示音修改都在事件入口再次檢查寫入資格。BroadcastChannel 不負責選主，也不轉送答案。

2. **接手一定重新讀存檔。**  
   主頁可在首頁且沒有未存進度時主動讓出，或關頁後釋放。等待頁取得鎖後重新讀取、建立新 session，不沿用等待期間的快照。不得因心跳逾時搶走背景頁的資格。不支援 Web Locks 時顯示無法安全儲存並停用修改。

3. **載入完成後，主頁記憶體是唯一工作狀態。**  
   作答只修改目前 state，`save()` 直接序列化它，不再 `fresh()` 或 `merge()`。日期仍供複習排程使用；時間戳不再決定寫入先後、清除或隱藏結果。

4. **區分「本頁已接受」與「已存到裝置」。**  
   作答、隱藏、恢復、提示音変更後可立即更新畫面；寫入失敗保留記憶體並設 `DIRTY`。首頁與題目畫面都顯示「還沒存好，請先不要關閉這頁」。提供手動重試及單一重試計時器；計時器每次寫**當下完整 state**，不保存舊快照、不重播答案。

5. **清除使用候選狀態，成功才公布。**  
   候選狀態只有 `it={}`，保留目前記憶體的隱藏與設定。寫入成功才採用候選、結束複習、顯示成功；失敗則保留清除前的 state、session、DIRTY，且不排入日後自動清除。

6. **所有畫面操作綁定世代與題目。**  
   寫入資格、載入狀態、session 世代、畫面世代及 `questionId` 必須一致才接受答案。答案接受一次即消耗該題操作資格。隱藏當前題、換題、清除及接手後，舊 handler 不得作用到新題。

7. **明確遷移，不能把讀不到當空白。**  
   保留 localStorage key `g5wrong.v1`，建議內容升為 `v:2`；保留既有學習欄位，隱藏名單改成 `true／不存在`，移除 `t/resetAt` 的合併用途。  
   舊 `v:1` 遷移時，`hidden:true` 或正數轉成隱藏，負數轉成恢復；舊紀錄依既有 `t >= resetAt` 判準整理一次，缺少兩者視為零。相等時間曾造成的清除歧義無法追溯推定，保留資料，讓家長重新清除。未知版本或壞格式須阻擋，不能 `clean()` 成空白再覆寫。遷移寫入失敗時，原始字串不變且不開放作答。

**同步必須納入唯一寫入者契約。**

[已驗證] 錯題站目前傳給 `G5Sync.init()` 的是 `onReplaced → reload`，沒有傳入設計 C 的 `canReplace/accept`。[src/app.html:399](/Users/william/Documents/g5-wrong-review/src/app.html:399)

推薦契約為：只有主頁初始化同步；同步只能提交候選資料，由主頁重新檢查資格並寫入。新裝置確實沒有本機 key、尚無本機操作時才可接受首次下載；**清除後的空紀錄仍是已存在的本機資料，不得被當作新裝置重新下載舊進度。** 已有資料發生分歧時各自保留，依設計 C 不提供覆蓋選擇。

共用 `sync.js` 是否實際支援此契約、其他入口是否也會寫此 key：**此點需擴大讀取範圍，未執行。** 未驗證前，方案（b）的安全落地版本應暫停錯題站同步初始化並顯示「跨裝置同步暫停，進度先存在這台裝置」，不能保留直接替換流程卻宣稱只有一個寫入者。

上線亦須處理仍開著的舊版分頁；新鎖無法約束不使用鎖的舊程式。此項是部署前提，不能靠新頁面內的測試假裝已解決。

## 實作與設計書的差異：同步替換條件

（2026-10-13 補，回應 Codex 審 1ed44f8 F1；本節是實作紀錄，不是 Codex 設計者原文。）

設計書第 3 節寫「新裝置確實沒有本機 key、尚無本機操作時才可接受首次下載」，矩陣 32 寫「已有不同本機資料時……全部拒絕」。實作**沒有照字面只接受首次下載**，分工如下。

**頁面端（錯題站）只管「現在能不能換」**：`src/core.js` 第 394 行 `canReplace` 在主頁、READY、在首頁（沒有練習 session）、沒有未存進度（DIRTY）、本頁取得寫入資格後還沒有自己的修改（`touched`）時才回 true。作答、隱藏、提示音、清除都會設 `touched`（第 339、362、370、379 行），取得寫入資格重讀存檔時重設（第 283 行）。`accept`（第 395 行起）會再檢查一次，只收合法的 v2，寫進主 key 成功才換記憶體。

**「該不該換」由 sync.js 判斷**。固定版本是 `tests/vendor/g5-help-sync.js`：協調視窗以 git show 匯出的 g5-help 已提交版（scratchpad 的 `sync_main.js`，sha256 `40c30e73a42da39cab805cbfcff6e23e75909518ffb231d58a0c2d2ddb35f183`），下列行號都指這份。它的 `recover()`（第 426–462 行）只有兩種情況會呼叫 `replaceLocal`。`replaceLocal` 在第 354–376 行：第 361 行先問 `canReplace`，第 365 行備份本機，第 369 行呼叫 `accept`。兩種情況是：

1. 沒有 baseline（這台從未和這個家庭碼同步過），而且本機 key 為 null：第 448–449 行。這是真正的新裝置首次下載。
2. 有 baseline、沒有 pending、`cloud.rev > baseline.rev`，而且 `contentHash(本機) === baseline.hash`（本機自上次確認同步後沒改過）：第 456–457 行。這是另一台前進了、這台沒動。

其餘情況都不替換。本機有未上傳的改動（包括清除後的空紀錄），一律 `startPending` 上傳（第 445、461 行）。雙方都改過、或無法確認是哪一台寫的，一律 `showConflict` 各自保留（第 441、443、450、455、458 行）。

**為什麼不照字面只接受首次下載**：情況 2 是「換電腦或 iPad 也能接著練」唯一的下行路徑。B 台同步過、有 baseline 之後，A 台練習並上傳（雲端 rev 前進）。B 台下次開啟時本機等於 baseline、雲端較新，只有換上才拿得到 A 台的進度。頁面若一律拒絕，sync.js 會記成 deferred 並設 `needsGet`（第 361–362、369 行），之後每 4 秒（第 697 行 `setInterval`）重抓一次雲端，卻永遠換不上。B 台一練習，本機就不等於 baseline、雲端又較新，第 458 行 `showConflict`「各自保留」，兩台從此各走各的、互相收不到進度。跨裝置同步就只剩「第一次下載」加「各自上傳」。

**實測證據**：`tests/e2e_sync.py` 在真瀏覽器裡，頁面載入上述固定版 sync.js（加 `--sync live` 改載正式網址那份），GAS 端點換成照 `g5-help/gas/core.js` get／put 加 rev 協定寫的記憶體假後端，Chromium、WebKit 各跑一輪：

- (i) 本機有資料、從未同步、雲端有資料：不替換，本機存檔逐字不變，雲端也不被覆寫，`canReplace`、`accept` 都沒被呼叫。
- (ii) 已同步、本機沒改、雲端被另一台更新：重新開啟時經頁面 `accept` 換成雲端版，換之前 sync.js 先備份本機，baseline 前進。
- (iii) 已同步、清除成功並已存、重新載入時雲端仍是清除前的版本：上傳清除後的狀態（雲端 rev 2、`it` 空），舊紀錄不復活，`accept` 沒被呼叫。
- (iv) 已同步、離線答題（本機不等於 baseline）、雲端被另一台更新：不替換，本機保留，雲端也不被覆寫，同步面板寫「兩台的紀錄不一樣」。

這支在 1ed44f8 與修正後都通過。它是行為證據，不是回歸測試，這部分的行為沒有改。

**殘留風險**：

- 頁面端的 `canReplace` 不知道 sync.js 的 baseline。「本機自上次同步後沒改」這個條件由 sync.js 保證。sync.js 改版時（例如 g5-help 工作樹裡尚未提交的版本），要把新檔換進 `tests/vendor/` 並更新 `tests/e2e_sync.py` 的 `PIN_SHA`，或用 `--sync live` 重跑。
- 本頁有過自己的修改並已上傳之後，若另一台又前進了，這一頁要重新開啟網站才會換上（`touched` 只在取得寫入資格時重設）。在那之前 sync.js 每 4 秒重抓一次，狀態列寫「回到首頁、存好後就會換上」，對這種情況不準確。若在重新開啟前又在這一頁練習，會走 `showConflict` 各自保留。
